# JAX Kernel Fusion in Climt

This document explains the concept of kernel fusion and how it is implemented in `climt` using the JAX backend to achieve near-native performance on CPUs.

## 1. The Concept: "Death by a Thousand Cuts"

In standard climate modeling frameworks (and the original `climt` NumPy backend), model components are executed sequentially. Each component reads data from RAM, performs a small amount of math, and writes the results back to RAM.

**Example Process (NumPy):**
1.  **Optical Depth**: Compute $	au$ for all cells $ightarrow$ Write to RAM.
2.  **Radiation**: Read $	au$ from RAM, compute fluxes $ightarrow$ Write to RAM.
3.  **Update**: Read fluxes from RAM, compute heating $ightarrow$ Write to RAM.

The bottleneck is not the math, but the **memory bandwidth**. Moving data between the CPU and RAM is orders of magnitude slower than the actual computation.

## 2. The Solution: Kernel Fusion

Kernel fusion is the process of combining multiple separate mathematical operations into a single machine-code loop. When using `JaxBackend`, the XLA (Accelerated Linear Algebra) compiler identifies dependencies between components and "fuses" them into a single kernel.

### Conceptual Loop Transformation
Instead of multiple loops over the grid, XLA generates one:

```python
# Conceptual loop generated by XLA
for cell in grid:
    # 1. Compute tau
    temp_tau = compute_tau(p[cell])  # Stays in CPU register
    
    # 2. Immediately compute radiation
    temp_flux = compute_flux(T[cell], temp_tau) # Stays in CPU register
    
    # 3. Store final result
    out_flux[cell] = temp_flux # Single write to RAM
```

## 3. Achieving Fusion in Climt

To enable fusion, the Python interpreter must be removed from the middle of the component execution chain. This is achieved by wrapping component calls in a single function decorated with `@jax.jit`.

### Example: Fusing Radiation, Convection, and Surface
```python
import jax
import climt

# 1. Enable JAX Backend
climt.set_backend(climt.JaxBackend())

# 2. Define the fused step
@jax.jit
def model_step(state, dt):
    # Component 1
    tend_lw, diag_lw = radiation_lw.array_call(state)
    
    # Component 2 (Shared state allows XLA to optimize data flow)
    tend_conv, diag_conv = convection.array_call(state, dt)
    
    # Component 3
    tend_slab, diag_slab = slab.array_call(state, dt)
    
    # The Fusion Point: State Update
    # Instead of T = T + tend1*dt then T = T + tend2*dt,
    # XLA generates: T_new = T + (tend1 + tend2)*dt in one step.
    new_state = update_function(state, tend_lw, tend_conv, tend_slab, dt)
    
    return new_state, {**diag_lw, **diag_conv, **diag_slab}
```

## 4. Performance Comparison

| Feature | Standard Climt (Numba) | Fused Climt (JAX) |
| :--- | :--- | :--- |
| **Inside Component** | Fast (Compiled LLVM) | Fast (Compiled XLA) |
| **Between Components** | **Slow** (Python Interpreter) | **Fast** (Compiled into the same loop) |
| **Memory Access** | Multiple RAM read/writes | Data stays in CPU Cache (L1/L2) |
| **Optimization Scope** | Single component | Entire model graph |

## 5. Ultimate Fusion: Whole-Model JIT

By using `jax.lax.scan`, it is possible to JIT-compile the **entire simulation loop**. This allows a model to run for thousands of timesteps (e.g., a 1,500-day GCM run) as a single execution on the CPU, returning control to Python only when the simulation is complete. This removes the "Python tax" entirely from the production run.
