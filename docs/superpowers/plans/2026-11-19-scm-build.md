# A compiled single-column run — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `climt.build_column_model(...)` turns sympl components, an example state and a timestep into a model that runs many single-column scenarios with no sympl, unyt or pint object touched inside the time loop, matching the equivalent sympl loop.

**Architecture:** Approach C of the spec. `climt/_core/compile.py` resolves units, dimensions and aliases once per component (`compile_component`); `climt/_core/column_model.py` composes compiled components into one step (diagnostics, tendencies, Euler or Adams–Bashforth, steppers, prescribed quantities) and drives the time loop in Python over raw arrays. Scenarios are columns; per-scenario parameters reach numba kernels as per-column arrays (`per_column`), and RRTMG's per-call stellar irradiance by grouping columns.

**Tech Stack:** numba 0.68, NumPy, sympl 0.5.x (`get_numpy_arrays_with_properties`, `sympl._core.wildcard.get_wildcard_matches_and_dim_lengths`, `DataArray.to_units`), unyt backend, xarray, pytest.

**Spec:** `docs/superpowers/specs/2026-11-19-scm-build-design.md`. Runs after `2026-11-19-numba-ports.md` and `2026-11-19-cffi-fortran.md` are complete on this branch; uses `climt/_core/parameters.py` (`per_column`, `PARALLEL_MIN_COLUMNS`) from the first.

## Global Constraints

- The sympl loop is the oracle. Single calls: `rtol = 1e-12, atol = 0`. Runs: every stored step at `rtol = 1e-12, atol = 0` over 50 steps. If a run diverges, match sympl's order of operations (tendencies summed in component order; the Adams–Bashforth expressions of `sympl/_components/timesteppers.py`), never loosen the tolerance.
- Nothing inside `ColumnModel.run`'s loop calls pint, unyt, xarray or `DataArray` methods.
- Every unsupported configuration is a `climt.CompileError` at build time naming the component and the reason: sympl wrappers (`UpdateFrequencyWrapper`, `TimeDifferencingWrapper`, `ScalingWrapper`), time stepping other than `"euler"` and `"adams_bashforth"` (orders 1–4, default 3), an input missing from the state, units not convertible affinely, a tendency of a quantity in an offset unit (`degC`), a diagnostic produced twice, a per-scenario parameter the component does not declare.
- The sympl path of every component gives identical numbers before and after this plan, except as stated for per-column parameters (the scalar case stays identical); the existing suite is the check.
- `import climt` imports nothing new at module level.
- Both state containers work: `sympl.DataArray` and `UnytStateContainer`.
- **How to run.** `$PY` is shorthand: write it out as `/Users/joymonteiro/miniconda3/envs/climt-scm/bin/python`, from this worktree. Tests: `$PY -m pytest <path> -q`; suite: `$PY -m pytest -m "not slow" -q`.
- flake8 (`tox.ini`) passes on `climt`. `HISTORY.rst` Unreleased gets an entry; version not bumped. Nothing is pushed.

## Review Focus

1. **A state whose units or dimension order differ from the components'** (pressure in hPa, temperature as `(lon, lat, mid_levels)`): compiled calls and runs equal sympl's. Test in Task 1.
2. **A one-column example state expanded to many scenarios where only some quantities vary**: columns that share inputs and parameters give identical results to each other, and each equals a sympl run of that scenario alone. Test in Task 5.
3. **Calling `run` twice** (continuing a run): the second call starts from where the first stopped, including Adams–Bashforth history; two runs of 25 steps equal one of 50. Test in Task 5.
4. **numba's thread count after `run`** (including when `run` raises): restored to what it was. Test in Task 6.
5. **A per-scenario value with the wrong shape or units** (length n−1; a 2-D array for a scalar parameter): a `ValueError` naming the quantity or parameter at build time, not a numba typing error inside the loop. Test in Task 5.

class CompileError(ValueError): ...   # so scenario errors (ValueError) and build errors share a base

class ArraySpec(NamedTuple):
    units: str
    dims: tuple        # of str
    shape: tuple       # of int

class CompiledComponent:
    component                     # the component it was built from
    kind: str                     # "tendency" | "implicit" | "diagnostic" | "stepper" (stepper in Task 2)
    takes_timestep: bool          # implicit and stepper
    inputs: dict                  # {name: ArraySpec}, canonical form
    tendencies: dict              # {name: ArraySpec}
    diagnostics: dict             # {name: ArraySpec}
    outputs: dict                 # {name: ArraySpec}; steppers only (Task 2), else {}
    def extract(self, state) -> dict          # {name: ndarray} copies, canonical form, via the active sympl backend
    def __call__(self, raw, timestep=None, time=None) -> tuple
        # (tendencies, diagnostics) — or (diagnostics, outputs) for a stepper — raw arrays in canonical form.
        # timestep: seconds (float), required iff takes_timestep, else TypeError containing "timestep".
        # time: datetime placed in the component's raw state as "time" when given. raw is not modified.
    def restore(self, first, second) -> tuple # wraps outputs as sympl quantities of the active backend

def compile_component(component, state) -> CompiledComponent
```

**Canonical form:** an input keeps the units string and dimension order it has in `state`. A tendency of a quantity in `state`: units `"(<state units>) / s"`, the state's dims and shape. A diagnostic in `state`: the state's units and dims. A diagnostic or tendency of a quantity not in `state`: the component's declared units; dims as declared, `"*"` replaced by the wildcard dims in the order sympl matched them.

**Done once by `compile_component`:**
1. Accept `TendencyComponent`, `ImplicitTendencyComponent`, `DiagnosticComponent` instances with `array_call` (and `Stepper`, Task 2). Anything else, including sympl's wrappers, raises `CompileError` naming the class. A missing input raises `CompileError` naming the quantity.
2. Wildcard names and dim lengths from `get_wildcard_matches_and_dim_lengths(state, component.input_properties)`.
3. Per input: the affine map from state units to component units by converting 0, 1 and 2 with the backend's unit conversion (`scale = f(1) − f(0)`, `offset = f(0)`; if `f(2)` differs from `offset + 2·scale` by more than `1e-9·max(1, |f(2)|)`, or conversion raises, `CompileError` naming the quantity and both units). Then the dimension plan: insert length-one axes for dims the state lacks, transpose to the component's order (wildcard expanded), broadcast, flatten the wildcard block. The component receives the array under its alias if it declares one.
4. Per output: the inverse dimension plan and the unit scale to canonical units. Tendency dims: `tendency_properties[name]["dims"]` if given, else those of the input of that name. A tendency of a quantity whose state unit has an offset raises `CompileError` naming the quantity and suggesting `degK`.
5. Scale 1 and offset 0 are skipped at call time.

At call time only NumPy array operations run.

def build_column_model(state, *, timestep, tendency_components=(), diagnostic_components=(),
                       steppers=(), time_stepping="adams_bashforth", order=3,
                       prescribed=(), scenarios=None, threads=None) -> ColumnModel
    # timestep: datetime.timedelta (or UnytTimeDelta); scenarios and threads: Tasks 5 and 6

class ColumnModel:
    state: dict             # current raw arrays, canonical form, every quantity any component reads or writes
    time: datetime.datetime
    def step(self) -> None  # one step, in place
    def run(self, n_steps, output_every=1, outputs=None) -> RunResult   # Task 6 adds threads; here: a Python loop over step()
    def to_state(self, scenario=None) -> dict   # sympl quantities of the active backend (scenario: Task 5)

class RunResult:
    times: list             # datetimes of the stored steps
    arrays: dict            # {name: ndarray of shape (n_stored, *canonical shape)}
    specs: dict             # {name: ArraySpec}
    def to_xarray(self) -> "xarray.Dataset"   # dims ("time", *spec.dims); units in attrs
```

**One step** (as `examples/gmd_radiative_convective_unyt.py` does it): diagnostic components on state *n*, outputs written into the state; tendency components each on the same state *n*, tendencies of one quantity summed in component order, diagnostics merged (a name produced by two components, or by a component and a diagnostic component, is a `CompileError` at build time naming both) and written into the state after the update; the time-stepping update of every quantity with a tendency (`"euler"`, or `"adams_bashforth"` with sympl's coefficients and its start-up at lower order, history kept on the model); each stepper in order on the updated state, its diagnostics and outputs written into the state; prescribed quantities reset to their values at build time; `time += timestep`. A component reading `time` gets the model's current time.

### Task 5: Scenarios

**Files:**
- Modify: `climt/_core/column_model.py`, `climt/_components/rrtmg/sw/component.py`, `tests/test_column_model.py`

**Interfaces:**
- Consumes: `with_parameters` (Task 3); `ColumnModel` (Task 4).
- Produces:

```python
class Scenarios:
    def __init__(self, n: int, inputs: dict = None, parameters: dict = None): ...
    # inputs: {quantity name: array} in the example state's units; shape (n,) (one value per scenario,
    #   broadcast over the quantity's other dims) or (n, *quantity shape without its horizontal dims).
    # parameters: {(component, name): array of shape (n,)}; name in type(component).per_column_parameters
    #   or in type(component).grouped_parameters.
```

- Columns: if every horizontal dim of the example state has length 1, `build_column_model` builds an expanded state with `lon` of length `n` (each quantity with a `lon` dim repeated; others unchanged) and compiles on it; scenario `i` is `lon` index `i`. If the state already has `n` columns, scenario `i` is flattened horizontal index `i` (C order). Any other count is a `ValueError` naming both numbers.
- Per-scenario inputs overwrite their columns before the run; a prescribed quantity is reset to its per-scenario value each step.
- Per-column parameters: each affected component is replaced in the model by `with_parameters(component, values, n)`.
- Grouped parameters: `RRTMGShortwave.grouped_parameters = {"stellar_irradiance": "_solar_const"}` (public name → attribute holding the per-call value). The model sorts columns into groups of equal value and, per step, calls a copy of the component with that attribute set, on each group's columns, writing results back to those columns. At build time it warns (`UserWarning`) with the number of groups when there is more than one. A name in neither declaration is a `ValueError` naming the component, the parameter and the declared names.
- Shape or length errors in `Scenarios` are `ValueError` naming the quantity or parameter.
- `to_state(scenario=i)` returns column `i` as a one-column sympl state.
