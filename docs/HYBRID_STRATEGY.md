# ML Strategy: Dynamic Parameter Prediction for the Emanuel Convection Scheme

This document outlines a comprehensive machine learning strategy for predicting internal configuration parameters (like entrainment rate `ENTP` and precipitation fall speed `OMTRAIN`) of the Emanuel convection scheme dynamically. 

This approach uses a Neural Network (NN) embedded directly into the physical model (as demonstrated in `predict_parameters.py` and `predict_parameters_extremes.py`), where the loss is computed *through* the differentiable physics solver.

---

## 1. Data Generation and Processing

Since the Neural Network is trained end-to-end through the JAX-compiled physics scheme, we need paired datasets of **Input Atmospheric States** and **Target Tendencies** (or target high-resolution observations).

### Input Data (Features)
The input to the NN is a single atmospheric column profile. For a model with `nlev` vertical levels, the state vector per column includes:
*   `T`: Air temperature profile (`nlev`)
*   `Q`: Specific humidity profile (`nlev`)
*   `U, V`: Horizontal wind profiles (`nlev` x 2)
*   `P, PH`: Mid-level and interface-level pressures (`nlev` + `nlev+1`)
*   `CBMF`: Cloud base mass flux from the previous timestep (1 scalar)

**Preprocessing:** 
All inputs must be normalized. Variables like specific humidity ($Q \sim 10^{-3}$) and pressure ($P \sim 10^3$) span vastly different orders of magnitude. 
*   Standardize $T, U, V$ using z-scores ($[x - \mu] / \sigma$).
*   Scale $Q$ by a constant (e.g., $10^3$) to bring it into the $[0, 1]$ range.
*   Normalize $P, PH$ using the surface pressure (e.g., $P / P_{surf}$).

### Target Data (Labels)
The targets are the "true" convective tendencies ($\Delta T$, $\Delta Q$, $\Delta U$, $\Delta V$). These can come from two sources:
1.  **Synthetic Truth (Proof of Concept):** Generated by running the Emanuel scheme itself with a known, fixed set of "true" parameters (e.g., `ENTP=1.5`, `OMTRAIN=50.0`).
2.  **High-Resolution Ground Truth (Production):** Coarse-grained output from a Cloud-Resolving Model (CRM) or Large-Eddy Simulation (LES) like SAM or System for Atmospheric Modeling.

### Sampling Strategy (Addressing Extremes)
Atmospheric datasets are heavily skewed toward stable, non-convecting states where tendencies are exactly zero.
*   **Stratified Sampling:** Under-sample stable profiles and heavily over-sample active convective profiles (where $CBMF > 0$ or CAPE $> 0$).
*   **Extremes Focus:** As demonstrated in `predict_parameters_extremes.py`, extreme precipitation events are rare but critical. Inject artificially warmed/moistened profiles into the dataset (e.g., $T_{surf} > 305$ K, $Q_{surf} > 0.020$ kg/kg) to ensure the network learns the parameter phase space that governs extreme instability.

## 2. Neural Network Architecture

The NN acts as a parameter generator $\theta = f_\phi(X)$, where $X$ is the column state and $\phi$ are the network weights.

### Architecture Choice: MLP (Multi-Layer Perceptron)
Since the physical processes parameterized by the Emanuel scheme are strictly column-local, a standard MLP (Fully Connected Network) is sufficient and highly efficient.
*   **Input Layer:** Dimension $5 \times nlev + (nlev+1) + 1$ (e.g., 182 for 30 levels).
*   **Hidden Layers:** 2-3 layers with 64-128 units each.
*   **Activation:** `ReLU` or `GELU`.
*   **Output Layer:** Dimension equals the number of predicted parameters (e.g., 2 for `ENTP` and `OMTRAIN`).

### Output Bounding (Crucial for Physics Stability)
The parameters of the Emanuel scheme have strict physical bounds (e.g., entrainment cannot be negative; fall speeds must be $>0$). 
If the NN predicts an invalid parameter, the internal physics solver will crash or produce NaNs.
*   **Activation:** Use `jax.nn.softplus(x)` on the final layer to ensure outputs are strictly positive.
*   **Scaling:** Scale the bounded output to sit near the physical defaults.
    ```python
    # Example: Softplus ensures > 0. Multiplying by the default centers the scale.
    entp = jax.nn.softplus(x[0]) * 1.5 
    omtrain = jax.nn.softplus(x[1]) * 50.0
    ```

## 3. Loss Formulation and Differentiable Physics

The most powerful aspect of this strategy is that we do **not** train the NN to directly predict the parameters (because we don't know the "perfect" parameters for a given CRM state). Instead, we train the NN to predict parameters that minimize the error in the **physics scheme's output tendencies**.

### The Forward Pass
1.  State $X$ is passed to the NN $\rightarrow$ predicts parameters $\theta$.
2.  State $X$ and parameters $\theta$ are passed to the differentiable Emanuel scheme $\rightarrow$ produces tendencies $Y_{pred}$.

### The Loss Function
We optimize the NN weights $\phi$ to minimize the Mean Squared Error (MSE) between $Y_{pred}$ and $Y_{true}$.

$$ L(\phi) = \frac{1}{N} \sum || Emanuel(X; f_\phi(X)) - Y_{true} ||^2 $$

Because the Emanuel scheme is written in JAX, the gradient $\nabla_\phi L$ flows cleanly backward through the complex physics loops, into the parameters, and back into the NN weights.

### Magnitude-Weighted Loss for Extremes
To capture rare, extreme events (as shown in `predict_parameters_extremes.py`), standard MSE is insufficient because the small number of extreme events are drowned out by the massive number of moderate events.
*   Apply an exponential weight based on the magnitude of the target tendency:
    $$ W = 1.0 + \exp(\alpha \cdot |Y_{true}|) $$
    $$ L_{weighted} = W \cdot L(\phi) $$
*   This forces the optimizer to take massive gradient steps when the NN fails to capture a severe convective updraft/downdraft.

---

## 4. Training Strategy

### Optimizer and Hyperparameters
*   **Optimizer:** Adam or AdamW (`optax.adamw`).
*   **Learning Rate:** $10^{-3}$ to $10^{-4}$ with a cosine decay schedule.
*   **Batch Size:** Because the Emanuel scheme evaluates independently per column, JAX's `vmap` allows us to compute massive batch sizes (e.g., 1024 or 4096 columns) entirely in parallel on a GPU/TPU.

### Gradient Clipping
The internal physics equations contain division by small numbers and exponential bounds. Early in training, a bad NN parameter prediction can cause massive gradient spikes to flow backward.
*   Use global norm gradient clipping (`optax.clip_by_global_norm`) to stabilize training.

### Online vs. Offline Training
*   **Offline Training (A priori):** Train the NN on a fixed dataset of CRM targets. This is fast and stable, but can lead to compounding errors when the NN is coupled back into the GCM, because the NN was only trained on "perfect" CRM states.
*   **Online/Rollout Training (A posteriori):** Run the physics scheme inside a simple 1D ODE solver during training. Compare the state after $N$ timesteps (e.g., 3 hours) to the CRM state, and backpropagate through time (BPTT). This prevents drift but is memory-intensive.

## 5. Validation and Evaluation Strategy

### 1. Tendency Evaluation (R2 and RMSE)
Evaluate the predicted tendencies ($Y_{pred}$) against the target tendencies ($Y_{true}$) on a held-out test set.
*   Calculate $R^2$ scores independently for Temperature and Moisture tendencies at different vertical levels (convection behaves very differently in the boundary layer vs. the upper troposphere).

### 2. Parameter Phase-Space Analysis
Since the NN is predicting physical parameters dynamically, evaluate *what* it learned:
*   Plot predicted `ENTP` vs. input `CAPE` or `CBMF`. Does the network learn to decrease entrainment during highly unstable events to allow deeper convection?
*   Verify that the predicted parameter distributions remain within physically defensible bounds.

### 3. Coupled Stability (The Ultimate Test)
A hybrid model is only successful if it remains stable when coupled to a fluid dynamics core.
*   Run a 1D Radiative-Convective Equilibrium (RCE) simulation using the trained NN + Emanuel scheme.
*   Run a full 3D idealized General Circulation Model (GCM) using the `sympl` / `climt` `HeldSuarez` dry core coupled to the hybrid scheme. 
*   **Metric of Success:** The model does not crash, the precipitation distribution matches the CRM, and the time-mean temperature/humidity profiles are physically realistic.
